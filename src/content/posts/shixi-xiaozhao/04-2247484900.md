一个为网安校招生的AI项目设计的agent防护中间件。

别上真实环境！

(全自动安全防护guard，攻防agent不再需要人工看守审批，保障低时延的情况，不再做出任何破坏性操作)

---

项目校招亮点：

思维亮点：大多数人在做具体攻防agent时，而你站在另一个维度维度，去做能解决一类问题的项目。(前提是攻防agent你也得会)

技术亮点：在攻防agent的loop编排，多层记忆，漏洞测试，上下文工程的基础上，探究agent恶意意图识别，意图漂移，agent的票据授予设计等技术。

最新技术落地：引入最近火爆的jev，直接实现jev在个人项目中的研究落地，展现你对新技术的积极拥抱。(其实决策模型很多，jev效果相比其它厂商并不算最好，但在校招项目中，jev就是首选)

1. 恶意意图识别

票面 intent 在 L0 就会被扫描。命中破坏性表述 → malicious ticket intent → 直接 deny，不进入后续向量、Jev 或沙箱。

目的很简单：带着「清库 / 抹掉用户表」这类意图进来的任务，不应靠后面的运气挡住。

2. 意图漂移识别

票写的是「只读」，调用却需要改写类能力——这就是 intent drift。

L0：call 所需能力不在票面能力内 → deny。网关对裁决再审一遍漂移，防止裁决被误用仍摸到执行出口。

漂移不是语法错误，是「票说的事」和「实际要干的事」不一致。OpGuard 把它当成硬拒绝，而不是警告。

3. 票据生成与校验（Intent Ticket）

每次作业先发 Intent Ticket：agent\_id、能力标签、资源范围、intent，并用 HMAC 签名。

无票 / 坏签 / 过期 → 拒。destroy 等破坏性能力签不出去。子票能力与资源必须是父票子集；漏挂守卫的子代理创建失败。

票把「这次允许做什么」说死；后面所有层都拿同一张票当前提。

![配图](/images/posts/2247484900/2.png)

4. 网关层防护（ExecPermit）

决策层产出 SignedVerdict 后，Gateway 二次复核：验签、TTL、资源范围，并重审硬拒 / 漂移 / 高相似。

通过后只签发短命 ExecPermit（约 30 秒）。执行层只认许可：裸 tool call → bypass\_rejected 并写审计。

决策管「该不该」，网关管「还能不能」，执行管「有许可才动」——三层不混。

![配图](/images/posts/2247484900/3.png)

5. 灰度沙箱 + Jev 兜底

分层短路，能早拒就早拒：L1 硬规则挡住明确破坏面；L1.5 语义向量高相似立即拒，中档才进 Jev；L2 Jev 为 JevAuditor 协议，可用 HttpJevAuditor（OPGUARD\_JEV\_URL）或 LLMJevAuditor，返回 allow / gray / deny，超时、传输失败、坏 JSON → deny；L3 灰度沙箱对灰区验效，硬拒路径不进沙箱。

Jev 不是万能裁判，而是中档兜底；沙箱是规则与语义仍说不清时的最后验效。整条链 fail-closed。

![配图](/images/posts/2247484900/4.png)

五道闸串起来：恶意意图与漂移在入口拦，票据定边界，网关只发短命许可，Jev 与灰度沙箱兜住中档与灰区。业务攻防工具仍由你自加；需要的是一条默认 deny、可挂到工具出口的执行闸。
